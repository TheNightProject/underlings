# Contributing

Underlings is source only: you build it on an Apple Silicon Mac, so that is where changes are
made and tested. Pull requests and issues are welcome.

## Set up

You need macOS on Apple Silicon, Node 22 and the Xcode Command Line Tools (`node-pty` builds
from source). Then, from the root of a checkout:

```sh
npm run setup      # installs the engine's and the app's packages
npm run build      # builds engine/dist and stamps build.json
```

`npm run app` builds and installs the app into `/Applications`. While you work, `npm start` in
`desktop/` runs the app on the checkout, and **Reload** at the foot of the rail picks up a change
to `lib/` and `ui/` without a rebuild.

## Layout

| Folder | Holds |
| --- | --- |
| `engine/` | the review engine in TypeScript: forges, Jira, agents, the queue and full auto |
| `lib/` | the worker's modules, plain ES modules |
| `ui/` | the page, plain scripts and styles joined in file order |
| `desktop/` | the Electron shell |
| `hooks/`, `scripts/` | Claude Code hooks, the release and build scripts, and the demo world in `scripts/demo/` |
| `docs/` | the manual |

## Test

```sh
npm test                # the engine's suite, then the worker's and the page's
npm run test:golden     # the GitLab and GitHub request baselines
npm --prefix engine run typecheck
```

`npm test` builds first. Tests never call GitLab, GitHub or Jira and never start a real
`claude`: each fakes the boundary it crosses and sets its own `HOME` and state folder, so
nothing is written to your real `~/.config` or `~/.local/state`. Keep it that way.

A change to behaviour comes with a test that fails without it. Run the new test against the old
code to see it fail before you rely on it.

Test data is invented. Use `example.com`, `acme/...` repos, `ABC-123` keys and made-up names,
never real people, employers or tickets. `lib/guard.test.mjs` fails on a list of things that must
not appear anywhere in the tree.

### The demo world

`npm run demo:serve` runs the real page and worker against an invented world: twelve or more
agents in every state, merge requests, tickets, Slack, email, a calendar and a game. It uses a
scratch home, a fake GitLab, Jira and Claude Code, and refuses every command and address outside
them, so nothing real is read or written. `npm run demo:capture` drives a scripted tour of it in
Chromium and writes the GIFs and `tour.mp4` in `docs/media/` that the README shows. It needs
`ffmpeg`, `gifsicle` and Chromium (`npm --prefix scripts/demo exec playwright-core install chromium`);
`--clip hero,agents` records only those clips, and `--out DIR` writes elsewhere. Everything visible
in it is invented; check each clip's contact sheet in the work folder before committing a new one.

### The golden baseline

`lib/fixtures/gitlab-golden/` records every request a full session makes to GitLab, the page's
text and the state it leaves, and `test:golden` fails if a change alters them, so a refactor
cannot start asking GitLab for more. When the change is deliberate, regenerate the baseline and
read the diff before committing it:

```sh
UNDERLINGS_GOLDEN=update npm run test:golden
git diff lib/fixtures/gitlab-golden
```

The GitHub baseline is checked the same way and never regenerated by that command: a change to
it is made by hand.

## Style

- **Comments** default to none. Write one only when the code cannot say it, and a reader who
  knows the language would otherwise get it wrong: why this way, a constraint from outside the
  file. One line, no ticket keys.
- Small functions with meaningful names, no deep nesting, and the simplest shape that works.
- British spelling in text a person reads, and no em dashes.
- TypeScript in `engine/` is strict. `npm --prefix engine run typecheck` must be clean.

## Commits and pull requests

- A GitMoji prefix and an imperative subject: `🐛 Keep the lock when a step is slow`. Put the
  issue number in the body or the pull request, not the subject.
- Split a pull request by kind where that helps a reviewer: fixtures, behaviour, docs.
- Describe what changed and why in a few lines. Say how you tested it.
- Raise a pull request as a draft until it is ready for review.

## Releases

`npm run release` stamps the version and writes the changelog section for it from the merged
pull requests since the last tag. See `docs/manual.md`, Releasing.

## Security

Report a vulnerability privately, as SECURITY.md describes, not in an issue.
